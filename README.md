# Steam Frame Walking Games

Treadmill VR games for Steam Frame, built on **Treadmill Frame XR Kit** with Godot
(`addons/treadmill_frame_xr_kit/`, MIT). This repo is both the kit's home and a starting template.

NOTE: This repo's code was generated by Claude Opus 5.5.

- **The kit:** everything reusable. See `addons/treadmill_frame_xr_kit/README.md`.
- **The demo:** `demo/forest_walk.tscn`, an endless dusk forest road with a waystone gaze test
  and positional forest sound. It's the main scene, and a worked example of using the kit.

## Starting a new treadmill game from this template

1. Copy the repo (or use it as a GitHub template). Keep `addons/`, `project.godot`,
   `export_presets.cfg` and `openxr_action_map.tres`.
2. Make your main scene: instance `addons/treadmill_frame_xr_kit/rig/tfx_rig.tscn` and give it a
   world (see the kit README). Set it as the main scene in Project Settings.
3. Delete `demo/` when you no longer need the example. Rename the project in Project Settings and
   change the Android package name in the export preset.

To add treadmill support to another existing project, copy just `addons/treadmill_frame_xr_kit/`.

## Running on the Frame (from a Mac, Android build)

1. On the Frame: Developer Mode on, then start **Lepton Development** from the Steam library.
2. On the Mac: `~/Library/Android/sdk/platform-tools/adb connect <frame-ip>:5555`
   If you get "no route to host": run `adb kill-server`, connect again, and check
   **System Settings → Privacy & Security → Local Network** for Godot and Terminal.
3. In Godot: **Remote Deploy → Steam Frame Lepton**. The "SteamFrame" Android preset has Gradle build,
   OpenXR, arm64 and the eye-tracking permissions.

The "Steam Frame Arm64" Linux preset is for native builds, uploaded with Valve's SteamOS Devkit
Client (Windows/Linux).

## First run on the headset

1. **B/Y → Treadmill → Measure treadmill.** Step off and touch the belt's front-left corner, then
   front-right, then the back end, with a controller tip, pulling its trigger each time.
2. **Trigger** switches to World view; the treadmill area stays see-through.
3. **Stride:** set the treadmill speed, walk until it says ready, then Calibrate. Repeat at a few speeds.

## Sound in the demo

All of these are positional, so you can place them by ear:

- **A bumblebee** visits every 25–60 seconds. Each visit is either a straight fly-by about 85 cm
  from your head, or 2–3 laps around you before it flies off. Find it by its buzz and look at it
  to "notice" it; this works once per visit.
- **Songbirds** sing from the trees and **crickets** chirp in the grass along the road. They go
  past you on the left and right as you walk.
- **Birds fly overhead**, chirping as they cross. You can hear the pitch shift as they pass.
- **An owl and a woodpecker** call from far away, from any direction, including behind you.
- **Wind in the trees** and a distant cricket chorus play as the background bed.

Settings → Sound has volumes, and a **Binaural cues** switch so you can hear the difference.
Headphones or the Frame's built-in speakers both work.

The sounds are synthesised by `demo/sounds/generate_sounds.py` (numpy + scipy). Replace any `.wav`
there with a real recording of the same name; use mono for positional sounds.

## Graphics test bench

**Settings → Graphics** has a live cost readout (GPU and CPU time per frame against the frame
budget, draw calls, triangles) and settings that apply at once:

- edge smoothing
- foveated rendering
- render resolution
- tone mapping
- sun shadows and shadow distance
- scenery density

The **Forest** tab switches the demo's look options on and off: tree shading, wind sway, soft fake
shadows under trees, ground detail, and real lantern lights.

Settings stay open in World view, so you can see the effect. Try each change, and compare the GPU
figure with the budget, which is 13.9 ms at 72 Hz.
